# Expense Tracker Go
This project is written in Go, intended to serve as APIs for an app to track expenses.

# Domain Explantion
## Expense
- Expense must be in one category.
- Expense can contain any number of tags.
- User can get expense list and expense detail
- User can add / update / delete expenses.
## Category
- There are 2 types of category: default category, custom category.
- Default categories are available for every user to select when adding a new expense.
- User can get category list and category detail
- User can add / update / delete only custom categories.
## Tags
- User can get tag list and tag detail
- User can add / update / delete tags.

# Project Explanation
## Technologies
- Written in Go.
- Use GORM as ORM
- Use Mockery to mock classes for testing.
- Use Makefile to make command simpler
## Project Structure
- `cmd`: contains codes related to command line
  - `cmd/api`: is for serving the APIs
  - `cmd/migrate`: is for running database migration
  - `cmd/seed`: is for running database seedings
- `internal`: contains all implementations for the app
  - `internal/apperror`: defines common error using in the app
  - `internal/model`: defines common model(s) using in the app
  - `internal/database`: contains codes related to database: databse connection, transaction, and seedings
    - `internal/database/seeds`: contains JSON seed files
  - `internal/middleware`: contains codes for middleware
  - `internal/util`: contains utils for the app implementation
  - `internal/testutil`: contains utils for testing such as test setup
  - `internal/auth`: contains codes for auth module
  - `internal/user`: contains codes for user module
  - `internal/expense`: contains codes for expense module
  - `internal/../mocks`: contains mocks of each module for testing (generated by Mockery)

# Running the app
Before serving the app, ensure the database is properly set.
To run database migration:
```bash
make migrate
```
To run database seeding for dev env:
```bash
make seed-dev
```
To run database seeding for prod env:
```bash
make seed-prod
```
Or in case of running in dev env, you may need to run migration and seeding in a single command:
```bash
make migrate-seed-dev
```
Once the database is ready, you can serve the APIs with this command:
```bash
make api
```

# Unit-testing
As mentioned earlier, this project uses Mockery to mock classes for testing.
So after any change to any interface, you need to generate new mocks:
```bash
go generate ./...
```
Note that you may need to remove the existing mocks before generating if there is any conflict.
When the mocks are all ready, run the unit-testing:
```bash
go test ./...
```
